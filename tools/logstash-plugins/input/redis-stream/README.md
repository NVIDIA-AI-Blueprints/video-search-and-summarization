# logstash-input-redis_stream

A Logstash **input** plugin (Java) for reading from Redis Streams using consumer
groups, with optional Protocol Buffer decoding.

## Introduction

`logstash-input-redis_stream` consumes entries from a Redis Stream via
`XREADGROUP` (consumer groups with acknowledgements), reads the payload as raw
bytes, and emits Logstash events. Payloads can be passed through as plain text
or decoded as Protocol Buffers (via a compiled Java class or a `.desc`
descriptor).

The built `.gem` is a **build artifact** — it is not committed to this repo.
Build it locally (below) and upload it manually to the deployment (see
[Output and manual upload](#output-and-manual-upload)).

## Getting Started

> These instructions target **Linux** (Ubuntu/Debian shown; adapt the package
> manager for other distros).

### Dependencies

1. [JDK 21](https://adoptium.net/) — the build compiles against Java 21 (Temurin recommended), matching Logstash 9.4.3
2. [Git](https://git-scm.com/)
3. Network access — the build downloads JRuby, Gradle, and Java dependencies (Maven Central)
4. A [Logstash](https://github.com/elastic/logstash) **source tree at `v9.4.3`** — provides
   `logstash-core.jar`, `versions.yml`, and `rubyUtils.gradle`, which the plugin build requires
   (see [Provide the Logstash core dependency](#1-provide-the-logstash-core-dependency))

Gradle itself does not need a separate install — the included wrapper
(`./gradlew`) downloads Gradle 8.7 automatically. JRuby is downloaded
automatically by the build at the version pinned in the Logstash `versions.yml`.

### Install prerequisites (Linux)

```bash
# JDK 21 + Git (Ubuntu/Debian)
sudo apt-get update
sudo apt-get install -y openjdk-21-jdk git

# verify
java -version   # should report 21.x
```

Alternatively, install JDK 21 with [SDKMAN](https://sdkman.io/):

```bash
curl -s "https://get.sdkman.io" | bash
source "$HOME/.sdkman/bin/sdkman-init.sh"
sdk install java 21.0.5-tem
```

## Building the gem

### 1. Provide the Logstash core dependency

The plugin build needs three things from a Logstash **source tree** (not just
the runtime image), all resolved relative to `LOGSTASH_CORE_PATH`:

- `logstash-core.jar` — the `co.elastic.logstash.api` classes to compile against
- `../versions.yml` — pins the JRuby version to download
- `../rubyUtils.gradle` — the Gradle tasks that package the gem (`downloadAndInstallJRuby`, `buildGem`, ...)

Clone the matching Logstash release and build its core:

```bash
git clone --depth 1 --branch v9.4.3 https://github.com/elastic/logstash.git
cd logstash

# Build logstash-core (produces logstash-core/build/libs/logstash-core-9.4.3.jar)
./gradlew assemble

# The plugin build looks for a file literally named 'logstash-core.jar' under
# LOGSTASH_CORE_PATH, so make one available:
cp logstash-core/build/libs/logstash-core-*.jar logstash-core/logstash-core.jar

cd -
```

### 2. Point the plugin at the Logstash core

Edit [`gradle.properties`](gradle.properties) and set the absolute path to the
`logstash-core` directory from the previous step:

```properties
LOGSTASH_CORE_PATH=/absolute/path/to/logstash/logstash-core
```

### 3. Build

```bash
./gradlew clean gem
```

This downloads JRuby, compiles the Java, shades the dependencies, generates the
Ruby support files, and packages the gem:

```text
logstash-input-redis_stream-3.3.0-java.gem
```

### 4. (optional) Run the Java tests

```bash
./gradlew clean test
```

## Output and manual upload

The build writes the gem into this plugin directory. It is **git-ignored on
purpose** — the gem is a build artifact and is not stored in the repo.

To use it, **copy the gem manually** to the location the deployment consumes
(renaming to the deploy gem name). The logstash service in
`deploy/docker/services/infra/compose.yml` mounts and installs the gem from the
deploy gems directory:

```bash
cp logstash-input-redis_stream-3.3.0-java.gem \
   <repo-root>/deploy/docker/services/infra/elk/logstash/gems/logstash-redis-stream-input-3.3.0-java.gem
```

> If you bump `VERSION`, the gem filename changes — update the destination and
> the compose mount reference accordingly.

## Configuration

Minimal pipeline:

```ruby
input {
  redis_stream {
    host       => "localhost"
    port       => 6379
    stream_key => "mystream"
    group      => "logstash_group"
    data_field => "value"
  }
}
output { stdout { codec => rubydebug } }
```

### Configuration Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `host` | string | `"localhost"` | Redis server hostname |
| `port` | number | `6379` | Redis server port |
| `password` | string | `nil` | Redis password (optional) |
| `stream_key` | string | `"mystream"` | Redis stream key to read from |
| `group` | string | `"logstash_group"` | Consumer group name |
| `block_ms` | number | `100` | Block timeout in milliseconds |
| `batch_size` | number | `100` | Maximum entries to read per batch |
| `create_group` | boolean | `true` | Auto-create the consumer group if missing |
| `data_field` | string | `"value"` | Field holding the message payload |
| `type` | string | `nil` | Event type to add to events |
| `decorate_events` | boolean | `true` | Add `redis_stream_id` / `redis_stream_key` metadata |
| `data_codec` | hash | `{}` | Payload decoding config (see below) |

### Protobuf decoding (optional)

Using a compiled Java class (on the classpath):

```ruby
data_codec => {
  "type"       => "protobuf"
  "class_name" => "nv.Schema$Frame"
}
```

Using a descriptor file (no compiled classes needed):

```ruby
data_codec => {
  "type"       => "protobuf"
  "class_name" => "nv.Frame"
  "class_file" => "/path/to/schema.desc"
}
```
