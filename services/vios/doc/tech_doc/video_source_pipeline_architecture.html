Video Source Pipeline Architecture

Refactored Design - Comprehensive Technical Documentation

Architecture Overview

The refactored video source architecture implements the Builder Pattern with clean separation of concerns:

CommonVideoSource (Controller)
↓
PipelineManager (Orchestrator)
↓
PipelineBuilder (Abstract Builder)
↓
SingleStreamPipelineBuilder | CompositePipelineBuilder

Key Benefits

  • Modularity: Each pipeline type has its own builder
  • Extensibility: Easy to add new pipeline types
  • Maintainability: Clear separation of pipeline construction logic
  • Backward Compatibility: Legacy interfaces preserved
  • Performance: Hardware acceleration and shared stream optimization

Build System Integration
New modular build system with standalone video source library

Components:

  • libnvvideo_source.so - Standalone video source shared library
  • Dependency Chain: webrtc_streamer → video_source → utilities
  • Modular Compilation: Independent building and testing
  • Resource Sharing: VideoSenderPool for efficient resource management
VideoSenderPool Resource Management
Efficient resource sharing for pass-through mode streaming

Key Features:

  • Singleton Pattern: Global access point for VideoWebRTCSender instances
  • URL-Based Sharing: Multiple clients share same VideoWebRTCSender for same stream URL
  • Memory Optimization: Prevents duplicate processing pipelines
  • Thread Safety: Mutex-protected operations for concurrent access
  • Automatic Cleanup: Shared pointer reference counting for lifecycle management
DecoderPool Resource Management
Efficient decoder instance sharing for regular mode streaming

Key Features:

  • Instance Reuse: Multiple consumers share same decoder for same stream
  • Lifecycle Management: Automatic creation, reuse, and cleanup
  • Resource Efficiency: Eliminates duplicate decoding processes
  • Thread Synchronization: Proper shutdown sequence with condition variables

Pipeline Selection Logic

Pipeline Type Selection

config.getCompositor().enabled
True: CompositePipelineBuilder
False: SingleStreamPipelineBuilder

Single Stream Type Selection

config.isPassThrough()
True: PassThroughPipeline
False: Continue to next condition
config.isNativeStream()
True: NativeStreamPipeline
False: Continue to next condition
config.isGodsEyeView()
True: GodsEyeViewPipeline
False: Continue to next condition
config.getOverlay().enabled && config.getOverlay().bboxEnabled
True: IPCPipeline
False: StandardPipeline

Composite Type Selection

config.isImageCapture()
True: ImageCapturePipeline
False: VideoCompositorPipeline

Error Handling and Recovery

Graceful Degradation
Pipeline continues operation with reduced functionality

Examples:

  • Overlay disabled if OSD libraries unavailable
  • Software encoding fallback if hardware unavailable
Component Isolation
Individual component failures don't crash entire pipeline

Examples:

  • Decoder pool management
  • Producer-consumer decoupling
Resource Cleanup
Proper cleanup during pipeline destruction

Examples:

  • Thread synchronization during shutdown
  • Component reference cleanup

Benefits:

  • Better resource utilization
