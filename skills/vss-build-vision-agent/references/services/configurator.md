# Blueprint Configurator Capability Owner

## Capabilities and service keys

| Capability | Canonical service profile keys | Foundation |
|---|---|---|
| Stream and hardware configuration rendering | `bp-configurator-<mode>`, `bp-configurator-<mode>-init` | `warehouse` |

`<mode>` is `2d` or `3d`; both use the container name `vss-configurator`.

> **`bp-configurator-<mode>-init` renders no config.** Despite the name it is a
> one-shot **broker readiness gate**: it polls Kafka/Redis and exits `0`. An
> `Exited (0)` is success.

## Required peers

- Required by **every** warehouse perception and analytics capability. The
  configurator writes the DeepStream and VST stream configuration the perception
  container and VIOS both read at start-up.
- `sensor-bp-wait-bp-configurator` gates VIOS sensor registration on this service
  becoming healthy — both are in the infrastructure floor
  ([`warehouse-infra.md`](warehouse-infra.md)).
- The `-init` gate additionally requires the selected broker.

## Environment is loaded outside Compose interpolation

This owner is the one warehouse service whose environment does **not** come from
Compose interpolation. It declares:

```yaml
env_file:
  - ${BP_CONFIGURATOR_BASE_ENV_FILE:-$VSS_APPS_DIR/.../.env}
  - ${BP_CONFIGURATOR_ENV_FILE:-$VSS_APPS_DIR/.../overrides.env}
```

Neither knob is set in any warehouse env layer, so by default the configurator
loads the **checked-in** `.env` and `overrides.env` directly and a build's
`override.env` never reaches it. The pristine `HOST_IP='<HOST_IP>'` sentinel is
then baked into the container that renders every stream and hardware config.

Set `BP_CONFIGURATOR_ENV_FILE` to a build-local file generated by
`scripts/render_warehouse_configurator_env.py` — see the artifact contract in
[`../composition.md`](../composition.md). This also affects the in-tree
`generated.env` workflow used by `vss-deploy-profile`, where editing
`generated.env` likewise does not change what the configurator reads.

## Configuration knobs

| Environment variable | Use |
|---|---|
| `HARDWARE_PROFILE` | Selects the perception tuning section in `blueprint_config.yml`. **Not validated by Compose** — an unrecognized value is accepted and matches no section, silently skipping the per-profile stream cap and tuning. |
| `PROFILE_CONFIG_FILE`, `CONFIGURATOR_CONFIG_FILE` | Select the configurator's config document. |
| `DS_CONFIG_DIR`, `NVSTREAMER_CONFIG_DIR` | Per-mode DeepStream and NVStreamer config directories. |
| `SENSOR_FILE_PATH` | Camera info JSON; derives from `VSS_APPS_DIR`. |
| `BP_PROFILE`, `MODE` | Drive the configurator's own validation gates. |

The configurator enforces three deployment constraints that fail at **runtime**,
not at `docker compose config` — `validate_warehouse_env.py` checks them ahead of
deploy:

1. `BP_PROFILE=bp_wh` in `2d` mode is rejected on `IGX-THOR` and `DGX-SPARK`.
2. `HARDWARE_PROFILE=DGX-SPARK` requires `PERCEPTION_TAG` to contain `sbsa`.
3. Sections exist for `H100, L4, L40S, RTXA6000, RTXA6000ADA, RTXPRO6000BW,
   RTXPRO4500BW, IGX-THOR, DGX-SPARK` — there is **no `OTHER`** section, though
   `OTHER` is valid for LLM NIM sizing.
