An *agent harness* is the coding agent or agent sandbox that is capable of loading the VSS
[Agent Skills](/vss/vision-agent/agent-skills) and to easily deploy and operate the vision-based microservices and workflows.
Because every VSS Skill follows the [agentskills.io](https://agentskills.io) specification, any
compatible harness can load the same Skills folder and drive VSS without bespoke
integration code.

The default runtime harness is OpenClaw managed by NemoClaw. Claude Code and
Codex are supported for development-time deployment and operations.

The following harnesses are validated against the VSS Agent Skills:

- **Claude Code** - Anthropic's CLI coding agent.
- **OpenAI Codex** - OpenAI's CLI coding agent.
- **OpenClaw** - the default runtime, with an `agentskills.io`-compatible host and chat UI.
- **NemoClaw** - NVIDIA's reference stack for running OpenClaw in an NVIDIA OpenShell sandbox.

<Note>
The default [VSS Agent](/vss/vision-agent/vss-agents) experience runs through
OpenClaw in a NemoClaw sandbox. It does not require the in-stack agent service.
For a comparison, see the [Quickstart](/vss/getting-started/quickstart).
</Note>

## How Harnesses Use VSS Skills

Regardless of which harness you choose, the model is the same:

1. **Install the Skills.** Each Skill folder from the `skills/` directory of the
   [VSS Blueprint repository](https://github.com/NVIDIA-AI-Blueprints/video-search-and-summarization/tree/develop/skills)
   is registered into the harness's standard skills directory (typically by symlink, so
   a `git pull` keeps every Skill current). See [Agent Skills](/vss/vision-agent/agent-skills) for
   the full install flow.
2. **Load the Skills.** On startup the harness reads each `SKILL.md` frontmatter and
   adds the Skill to its tool list. Start a new session before invoking a newly
   installed Skill.
3. **Match and invoke.** The harness matches a natural-language request against the
   Skills' descriptions and invokes the matching Skill - chaining several Skills when a
   task needs multiple steps or a missing prerequisite.

As described in [Usage Patterns](/vss/vision-agent/agent-skills#usage-patterns), harnesses are used
in two complementary ways:

- **Deployment.** A coding agent such as Claude Code or Codex loads the Skills and stands
  up a VSS profile from a request like *"Deploy VSS for video search"*.
- **Runtime.** NemoClaw runs OpenClaw with the same Skills as the operational
  chat interface to a deployed VSS stack.

## Claude Code

[Claude Code](https://docs.anthropic.com/claude/docs/claude-code) loads VSS Skills from
`~/.claude/skills/<name>/`. After cloning the VSS Blueprint repository, open it in
Claude Code and ask the agent to read `skills/README.md` and register each Skill into
that directory (see [Installing Skills](/vss/vision-agent/agent-skills)). Once the Skills are
installed, prompt Claude Code in natural language - for example, *"Deploy VSS for video
summarization"* or *"Add an RTSP camera at rtsp://10.0.0.5:554/stream1"* - and it invokes
the matching Skill such as `vss-build-vision-ai` or `vss-manage-video-io-storage`.

## OpenAI Codex

[OpenAI Codex](https://platform.openai.com/docs/codex) loads VSS Skills from
`~/.codex/skills/<name>/`. The install and invocation flow is identical to Claude
Code - point Codex at the cloned repository, have it register the Skills into the Codex
skills directory, and then drive VSS through natural-language prompts. The same Skills
catalog is used, so the available capabilities and example prompts are unchanged.

## OpenClaw

OpenClaw is the default runtime harness. It exposes an
`agentskills.io`-compatible host with a chat UI and loads VSS Skills from
`~/.agents/skills/<name>/`. Use [NemoClaw](#nemoclaw) to install and run it with
the VSS plugin, policy preset, and Orchestrator MCP configuration.

## NemoClaw

[NVIDIA NemoClaw](https://github.com/NVIDIA/NemoClaw) is the default way to run
OpenClaw with VSS inside an NVIDIA OpenShell sandbox. Instead of installing
Skills by hand, the bundled `deploy_nemoclaw.ipynb` and
`deploy_vss_orchestrator.ipynb` notebooks apply the VSS policy, install the repository's
VSS Skills and workspace docs into the sandbox, register the VSS Orchestrator MCP, and
start the [VSS Orchestrator MCP server](/vss/vision-agent/agent-harnesses/nemoclaw/vss-orchestrator-mcp) on the
host. From the chat UI you can deploy profiles, manage cameras and streams, query
incidents, run searches, summarize videos, and pull logs - with confirmation prompts
before destructive actions. For setup, configuration, and troubleshooting, see
[NemoClaw](/vss/vision-agent/agent-harnesses/nemoclaw).

OpenClaw is the default `AGENT_RUNTIME`. Select another supported runtime only
when your deployment requires it.

<Note>
The NemoClaw notebooks are released as an Early Access feature.
</Note>
