## Overview

The Real-Time VLM (RTVI-VLM) microservice processes live RTSP streams and recorded
videos in 10-second chunks. These VSS 3.3 measurements replace the VSS 3.2 results
previously published on this page. They cover the integrated vLLM backend, with
Adaptive EVS disabled and enabled, on one GPU per worker or one embedded device.
They do not measure a Dynamo deployment, an external NIM endpoint, or the
end-to-end video summarization workflow.

OSL=1 uses a binary alert prompt; OSL=100 uses a descriptive caption prompt.
Both are benchmark output-length settings, not recommendations for every application.
Adaptive EVS is the feature previously called EVS++.

## Reading the Results

- **Reported maximum live streams** is the capacity value found by the benchmark's
  ramp and binary search using a moving-average chunk-latency threshold of 10 seconds.
  It is not a p95 latency guarantee. Ramp runs can include dropped chunks while
  probing overloaded levels; revalidate the intended load and drop policy before deployment.
- **Single-stream latency** compares the same load with Adaptive EVS off and on.
  It is chunk-processing latency after frames are available, not TTFT or video capture time.
- **File throughput** counts completed 10-second files per second. The reported peak
  is the highest observed throughput among tested concurrency levels, not a proven ceiling.
  Off/on peaks can occur at different concurrency levels; use concurrency 1 for a matched-load comparison.
- **File latency** is the time to process an entire file at concurrency 1, without a
  downstream summarization LLM. Datacenter values average iterations 2 and 3,
  excluding the first warm-up iteration; embedded values use the workbook's three-run mean.

The tables summarize PBR 309400 (datacenter, report revision 4, October 22, 2026)
and PBR 309401 (embedded baseline and Adaptive EVS runs, October 2026).
No new benchmark runs were performed for this documentation update.

## Measurement Limitations

- Datacenter fixed-load live-stream tests with stream errors were excluded from
  latency reporting. The source report records errors at 100 of 359 tested load
  levels, predominantly at 64 and 128 streams. The single-stream table above uses
  only error-free measurements.
- Four datacenter Adaptive EVS-on capacity points use the benchmark harness fix
  from PR #2712: B200 and GB200 at 2K/OSL=1, and RTX PRO 6000 SE at 2K/OSL=100
  and 4K/OSL=100. The GB200 2K/OSL=1 on result uses a GB200 NVL4 node; the other
  GB200 measurements use a different cluster node configuration.
- Embedded capacity rows marked as reaching a capacity limit in the harness retain
  their measured stream count; this is distinct from a runtime error. Their workbook
  records zero dropped chunks at the reported capacity.
- Source videos, prompt, output length, model, precision, sampling profile, memory
  budget, and Adaptive EVS setting all affect capacity. Validate the intended
  application workload rather than treating any one stream count as universal.
