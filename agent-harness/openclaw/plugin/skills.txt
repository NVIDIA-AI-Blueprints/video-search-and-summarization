# Skills the VSS OpenClaw plugin ships, one per line: <skill-dir-name> <needs>
#
# Operation skills only: each drives a live deployment through the vss CLI's
# operation commands, which is what the vss_cli tool exposes. Deploy, benchmark
# and build skills stay in the repo's skills/ tree and are not in this image.
#
# <needs> is what the deployment must expose for the skill to be *active*:
#   a vss CLI command group (search, summarize, vlm, vios, memory) — active when
#     `vss configure check` reports the group available, i.e. the routes it
#     needs (search: elasticsearch + rt_embed; summarize: lvs; vlm: rt_vlm) were
#     recorded by `vss configure`;
#   alerts — active when the Alert Bridge answers at <base_url>/alert-bridge
#     (the haproxy/Ingress path) or on the Compose host port 9080.
# With no recorded deployment every listed skill is active, so the agent can
# still run `vss configure`. `vss-openclaw-sync` re-applies the selection.
vss-search-archive          search
vss-summarize-video         summarize
vss-ask-video               vlm
vss-generate-video-report   vlm
vss-manage-alerts           alerts
