# Evaluation V2: human review of the AI-generated references

The incident ground truth (`ground-truth-v1.0`, frozen 2026-10-28) is complete and is the reference for incident, object, token and latency results.

The **references for the other dimensions were generated by Claude and checked by a blind Claude validator. No record is human-verified.**
- **What the tiers mean:** `ai_validated` means only that two AI passes agree, not that the record is correct.
- **Rule:** an AI-tier record is **never** relabelled `human_verified` without a reviewer's decision. Results computed on AI-tier references are reported as provisional and labelled with the tier.

## 2. How to review (all sets)

- Work in the workbook only. Never edit `records.jsonl`; the review kit imports decisions (`python -m evalv2 review import` and `review apply`), which writes a new version.
- **Decision per row:**
  - **Approve:** the reference is exactly right.
  - **Correct:** right idea, wrong detail. Write the correction in the note column.
  - **Reject:** the question, request or box is wrong or ambiguous.
  - **Unsure:** needs discussion.
- **Judge against the frozen ground truth and the video,** not against model outputs. If the ground truth itself looks wrong, note it, but do not change it: GT corrections follow `ground_truth_correction.py` and need the owner.
- **Double review:** a second reviewer independently re-reviews 20% of each workbook, for inter-reviewer κ.

### RA2 chat questions
For each question, check three things:
1. **The question:** it is answerable from the report alone and does not leak its answer.
2. **The expected answer:** counts, values and lists match the code recount from the ground truth. The recount is shown; disagree only if the recount itself is wrong.
3. **Relevance labels:** the expected cited items and incidents are all relevant, and no relevant one is missing.

For the 10 retrieval questions, also check that the "target incidents" set is complete: are there other incidents that also match the description?

### RB2 dashboard requests
- Check that the request, read naturally, asks for exactly the expected chart: metric, dimension, period (the allowlist has rolling periods only, such as `last_30_days`; the blind validator read "last month" and "past week" as rolling. Decide whether the wording really means that, and mark it Unsure if not), and type and severity filters.
- For the 15 unsupported requests, check that the request really cannot be expressed with the allowlist.
- Record ambiguous wording as Unsure, not Approve.

### RA1 boxes (after generation)
For each sheet (one item, its numbered frames, the chosen box per second), check two things:
- The box covers the named item, tightly enough that a crop would show it.
- The seconds marked "not visible" really are not visible.

Reject any frame where the detector box shows a different object.
